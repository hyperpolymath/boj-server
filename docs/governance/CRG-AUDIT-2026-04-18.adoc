*Component Readiness Grades v2.0 (STRICT)*, 2026-03-30 revision.

- Standard: `standards/component-readiness-grades/COMPONENT-READINESS-GRADES.md`

== v2.0 Strictness Recap

[cols="1,3,4"]
|===
| Grade | Release Stage | Hard Requirement (v2.0)

| X | None             | Untested.
| F | Reject           | Harmful, wasteful, or superseded.
| E | Pre-alpha        | >=1 test, failures documented.
| D | Alpha            | Test matrix + scope documented + *RSR compliance mandatory*.
| C | Alpha-stable     | Dogfooded, CI green, *deep per-file + per-directory annotation*.
| B | Beta             | 6+ *diverse* external targets, issues fed back.
| A | Stable           | Real-world external feedback confirms value; no harm.
|===

Publication requires B+. Long alpha is discipline, not shame.

== Verdict

*Current CRG grade: **D (Alpha)**.*

This matches the self-declared `grade = "D-alpha"` in `STATE.a2ml` and the
2026-03-09 `READINESS.md` assessment. v2.0 strictness does *not* change the
outcome: the repo is firmly a solid D, with the C boundary within session-tractable
reach but genuinely unmet today.

The D grade is earned, not conservative-by-default:

- All 17 RSR mandatory workflows are present and active.
- 365 tests across core / cartridge FFI / federation / MCP bridge suites.
- Formal verification posture is strong (0 non-axiomatic `believe_me`, 4
  documented axiomatic primitives, `IsUnbreakable` proof type at the ABI layer,
  BJ2 credential-isolation module typechecks green).
- LIVE deployment is healthy on `boj-server.net`.

What blocks *immediate* promotion to C:

1. 46 of 99 cartridges lack `README.{adoc,md}` — "deep per-file annotation"
   clause fails.
2. `docs/READINESS.adoc` is on the v1.0 schema from 2026-03-09 and does not
   reflect v2.0 strictness, the 4-believe_me sweep, BJ2 closure, MCP bridge
   tests, or the v-sweep cartridge count (99). A stale readiness doc is itself
   an annotation defect.
3. No per-directory orientation README for `cartridges/`,
   `.machine_readable/`, `ffi/zig/src/` — v2.0 wants "per-directory
   orientation", not just top-level architecture docs.

What blocks promotion to B (even after C is met):

1. *No* external targets documented. The six Grade-B line items enumerated in
   `STATE.a2ml [grade-b-status]` are internal capabilities; v2.0 requires
   *external targets*, which are a different category entirely.
2. No recruited external dogfooders, no feedback pipeline, no issues-fed-back
   evidence.

== Notes on Non-Negotiables Respected by this Audit

- Four irreducible `believe_me` axioms in `src/abi/Boj/SafetyLemmas.idr` and
  `src/abi/Boj/SafeAPIKey.idr` are *not* listed as proof debt. They are named
  backend primitives, documented in file headers, and correct per design.
- BJ2 credential isolation (`src/abi/Boj/CredentialIsolation.idr`) is considered
  closed; no action is proposed against it.
- Irreducible `january-key` / `januskey` items (per user standing rule) are
  *not touched*.
