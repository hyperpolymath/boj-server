= User Guide

This guide is for people *using* a running BoJ server, either via the REST API or as an MCP server for AI tools.

== Quick Start (REST API)

[source,bash]
----
# Health check
curl http://localhost:7700/health
# {"status":"ok"}

# See server status
curl http://localhost:7700/status

# Browse the Teranga menu (what's available)
curl http://localhost:7700/menu

# View the full capability matrix
curl http://localhost:7700/matrix
----

=== Mount and invoke a cartridge

[source,bash]
----
# Mount the database cartridge
curl -X POST http://localhost:7700/cartridges/database-mcp/load

# Invoke a tool
curl -X POST http://localhost:7700/cartridges/database-mcp/invoke \
  -H 'Content-Type: application/json' \
  -d '{"tool":"list_octads","args":""}'

# Unmount when done
curl -X POST http://localhost:7700/cartridges/database-mcp/unload
----

=== Place an order (Order-Ticket Protocol)

[source,bash]
----
curl -X POST http://localhost:7700/order \
  -H 'Content-Type: application/json' \
  -d '{"cartridges":["database-mcp","observe-mcp"]}'
----

== MCP Mode (for AI Tools)

BoJ speaks MCP natively via JSON-RPC 2.0 over stdio. All 18 cartridges are exposed as MCP tools.

=== Claude Desktop / Claude Code

Add to your `claude_desktop_config.json`:

[source,json]
----
{
  "mcpServers": {
    "boj": {
      "command": "/path/to/boj-server",
      "args": ["--mcp"],
      "env": {
        "LD_LIBRARY_PATH": "/path/to/ffi/zig/zig-out/lib:/path/to/cartridges/container-mcp/ffi/zig-out/lib:/path/to/cartridges/feedback-mcp/ffi/zig-out/lib"
      }
    }
  }
}
----

Replace `/path/to/` with the actual path to your BoJ installation.

=== Other MCP clients

Any MCP-compatible client can consume BoJ. Start the server in MCP mode:

[source,bash]
----
LD_LIBRARY_PATH=ffi/zig/zig-out/lib \
  bash -c 'cd elixir && mix run --no-halt -- --mcp'
----

The server reads JSON-RPC 2.0 from stdin and writes responses to stdout.

== Common Workflows

=== Inspect what's available

[source,bash]
----
# Full menu with all three tiers (Teranga, Shield, Ayo)
curl http://localhost:7700/menu

# Just core cartridges
curl http://localhost:7700/menu/teranga

# Community cartridges
curl http://localhost:7700/menu/ayo
----

=== Check a specific cartridge

[source,bash]
----
curl http://localhost:7700/cartridge/database-mcp
----

=== Submit feedback

[source,bash]
----
# Mount the feedback cartridge
curl -X POST http://localhost:7700/cartridges/feedback-mcp/load

# Open a channel
curl -X POST http://localhost:7700/cartridges/feedback-mcp/invoke \
  -H 'Content-Type: application/json' \
  -d '{"tool":"open_channel","args":"{\"channel\":\"api\"}"}'

# Submit feedback
curl -X POST http://localhost:7700/cartridges/feedback-mcp/invoke \
  -H 'Content-Type: application/json' \
  -d '{"tool":"submit","args":"{\"slot\":\"0\",\"sentiment\":\"positive\"}"}'

# View summary
curl -X POST http://localhost:7700/cartridges/feedback-mcp/invoke \
  -H 'Content-Type: application/json' \
  -d '{"tool":"summary","args":""}'
----

=== Check federation status

[source,bash]
----
# See this node's federation status
curl http://localhost:7700/umoja/status

# List connected peers
curl http://localhost:7700/umoja/peers
----

=== Use gRPC-compat endpoints

[source,bash]
----
# Same operations via gRPC-style paths (JSON-over-HTTP on port 7701)
curl http://localhost:7701/boj.Catalogue/List
curl http://localhost:7701/boj.Menu/Full
----

=== Use GraphQL

[source,bash]
----
curl -X POST http://localhost:7702/graphql \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ status { version totalCartridges } }"}'
----

== Error Handling

All errors return JSON with an `error` field:

[source,json]
----
{"error": "cartridge not found: unknown-mcp"}
----

HTTP status codes: `400` (bad request), `404` (not found), `409` (conflict, e.g., already mounted), `503` (service unavailable).
