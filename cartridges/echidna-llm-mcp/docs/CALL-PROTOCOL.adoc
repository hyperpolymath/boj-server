== Rule Zero

**Never call ECHIDNA directly.  Always use the `echidna-llm-mcp` BoJ cartridge.**

The cartridge enforces the 30 s timeout, routes to the right backend URL,
and maintains the trust invariant that advisory suggestions cannot affect
prover trust levels (formally proved in `abi/EchidnaLlm/Protocol.idr`).

== Backend

All 15 tools route through a single ECHIDNA REST API endpoint:

[source,bash]
----
# Local (echidna --port 8081, the main.rs default)
export ECHIDNA_REST_URL=http://127.0.0.1:8081

# Fly.io private 6PN (production — used by nesy-solver-api, etc.)
export ECHIDNA_REST_URL=http://echidna-nesy.flycast:8090
----

If `ECHIDNA_REST_URL` is unset the cartridge defaults to `http://127.0.0.1:8081`.
Fly.io cold-start grace is 90 s (Isabelle heap maps on first use; Julia JIT
initialises on first `/api/suggest` call).

== 15 Tools at a Glance

[cols="2,1,3"]
|===
| Tool | HTTP | What it does

| `echidna_list_provers` | GET /api/provers | **Start here.** Returns all 105 provers: name, tier, complexity.
| `echidna_health` | GET /api/health | Is the backend up? Returns `{ status, version }`.
| `echidna_rank_provers` | GET /api/provers | Same list — sort by tier/complexity to pick the best prover.
| `echidna_aspect_tags` | GET /api/aspect-tags | Domain tags used by the tactic suggestion model.
| `echidna_prove` | POST /api/prove | Parse + prove a theorem. Returns `{ success, goals, message }`.
| `echidna_verify` | POST /api/verify | Parse → export → binary round-trip. Typed outcome.
| `echidna_verify_raw` | POST /api/verify_raw | Raw binary invocation (EProver, CaDiCaL, etc.).
| `echidna_suggest` | POST /api/suggest | GNN / Julia ML corpus-backed tactic suggestions.
| `echidna_suggest_tactics` | POST /api/tactics/suggest | Aspect-tag model — takes goal text. Advisory only.
| `echidna_search` | GET /api/search?q= | Keyword search over 66,674-proof corpus.
| `echidna_search_theorems` | GET /api/theorems/search?q= | Theorem metadata search.
| `echidna_session_create` | POST /api/session/create | Start interactive tactic session.
| `echidna_session_state` | GET /api/session/:id/state | Current goals + completion flag.
| `echidna_session_apply` | POST /api/session/:id/apply | Apply a tactic.
| `echidna_session_tree` | GET /api/session/:id/tree | Proof tree JSON.
|===

== Typical Workflows

=== 1. Discover Provers, Then Verify

[source,json]
----
{ "tool": "echidna_list_provers", "args": {} }

{
  "tool": "echidna_verify",
  "args": {
    "prover": "Lean",
    "content": "theorem zero_add (n : Nat) : 0 + n = n := Nat.zero_add n"
  }
}
----

Response shape: `{ valid, outcome, goals_remaining, tactics_used }`
Outcome is one of: `PROVED`, `NO_PROOF_FOUND`, `INVALID_INPUT`,
`UNSUPPORTED_FEATURE`, `TIMEOUT`, `INCONSISTENT_PREMISES`,
`PROVER_ERROR`, `SYSTEM_ERROR`.

=== 2. Prove with Neural Assistance

[source,json]
----
{
  "tool": "echidna_prove",
  "args": {
    "prover": "Coq",
    "content": "Theorem plus_comm : forall n m : nat, n + m = m + n.\nProof. intros. ring. Qed.",
    "neural": true,
    "timeout": 120
  }
}
----

=== 3. Get Tactic Suggestions

[source,json]
----
// Corpus-backed neural suggestions (Julia ML layer)
{
  "tool": "echidna_suggest",
  "args": { "prover": "Idris2", "content": "?hole : n + Z = n", "limit": 10 }
}

// Aspect-tag model (goal text in, tactics out — advisory only)
{
  "tool": "echidna_suggest_tactics",
  "args": { "goal": "n + 0 = n", "prover": "Lean", "top_k": 5 }
}
----

=== 4. SMT / ATP Raw Invocation

[source,json]
----
{
  "tool": "echidna_verify_raw",
  "args": {
    "prover": "Z3",
    "content": "(declare-const x Int)\n(assert (not (= (+ x 1) (+ 1 x))))\n(check-sat)"
  }
}
----

Expected: `{ valid: true, exit_code: 0, stdout: "unsat", stderr: "", message: "..." }`

=== 5. Interactive Tactic Session

[source,json]
----
// a. Open session
{ "tool": "echidna_session_create", "args": { "prover": "Coq" } }
// → { session_id: "abc123" }

// b. Apply tactics step by step
{ "tool": "echidna_session_apply",
  "args": { "session_id": "abc123", "tactic": "intros n." } }
{ "tool": "echidna_session_apply",
  "args": { "session_id": "abc123", "tactic": "ring." } }

// c. Confirm completion
{ "tool": "echidna_session_state", "args": { "session_id": "abc123" } }
// → { goals: 0, complete: true }
----

== Error Responses

All tools return `{ status: int, data: object }`.

[cols="1,3"]
|===
| Status | Meaning

| 200 | Success
| 400 | Bad request (malformed prover name, missing required field)
| 404 | Unknown tool, session not found
| 503 | ECHIDNA backend unavailable — check `ECHIDNA_REST_URL`, wait 90 s for cold start
| 504 | 30 s cartridge timeout exceeded
|===

== Adding ECHIDNA to a New Repo

1. Add to `.machine_readable/6a2/ECOSYSTEM.a2ml`:
+
[source,toml]
----
{ name = "echidna", relationship = "active-integration",
  notes = "Proof verification via echidna-llm-mcp BoJ cartridge." }
----

2. Add the call-protocol snippet to `0-AI-MANIFEST.a2ml` (see any existing
   consumer repo, e.g. `verification-ecosystem/proven-servers`).

3. Set `ECHIDNA_REST_URL` in `fly.toml` or your local shell profile.

4. Never import the echidna Rust crates or call the REST API directly —
   always go through the `echidna-llm-mcp` cartridge.

== Trust Model

`echidna_suggest` and `echidna_suggest_tactics` are **advisory only**.
Their output is never fed back into the ECHIDNA trust pipeline.
This is formally proved in `abi/EchidnaLlm/Protocol.idr::allOperationsAdvisory`.

`echidna_prove` and `echidna_verify` run the full 11-step trust pipeline:
solver binary integrity (SHAKE3-512 + BLAKE3), SMT cross-checking, proof
certificate verification, axiom tracking, sandboxing, and confidence scoring.
